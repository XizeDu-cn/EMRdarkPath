## 二　只在对话中给出的结论（摘要）

### 2.1　顶会坐标

- 文本病历生成进入 ICLR、ACL 正刊这一档的，目前只有 LLM-CARe（ICLR 2026）。
- RareSyn 在 EMNLP（CCF-B）。
- ClinGen、NoteChat、Asclepius、MedSSR 在 Findings。
- 结构化电子病历生成另有一条扩散模型线：FLEXGEN-EHR（ICLR 2024）、EHRPD（KDD 2024）、TarDiff（KDD 2025）等。
- 三篇被审论文都没有引用 ClinGen 或 AttrPrompt。

### 2.2　国外做合成数据最在意的五件事

1. 在真实测试集上有没有增益，是否与"用真实数据训练"并列对比；
2. 生成内容是否正确、能否核验；
3. 多样性和覆盖面，以及模型坍塌；
4. 隐私：记忆检测、近重复检索、差分隐私；
5. 算力对齐的朴素对照。

### 2.3　四篇对照（ClinGen 加入后）

- **ClinGen**：
  - 实验范式最接近国外主线：18 个真实测试集、同一生成器下对比、量了分布距离；
  - 缺去噪、联合分布、隐私审计；
  - 知识图谱只用成了一张实体名词表；
  - 本质是 AttrPrompt 的医学版，AttrPrompt 的第一、第二作者都是 ClinGen 合作者。
- **LLM-CARe、RareSyn、NHS**：分别在"评委即作者""证据不可核实""篇间不比较"上回避了核心问题，详见审计卡。
- **将来拿 ClinGen 做对比时**：
  - 统一到同一个下游考场；
  - 换成与本方法相同的生成器；
  - 说明关键词表是重建的。

### 2.4　候选新题：可验证一致性奖励训练病历生成器

**国外近作各做了一半：**
- Synthetic Hospital（CMU，2026-09）搭了可核验的纵向考场，但没训练任何模型；
- GDP（npj Health Systems，2026-06）的忠实度靠人工打分；
- RLSyn 用强化学习训练生成器，但奖励来自判别器，不可核验，且生成的是表格数据。

**空白：** 以结构化病人记录为真值，用程序检查笔记与记录是否一致，把检查结果作为强化学习奖励，最后在真实数据上考试。

**风险：** 题目被 CMU 点名，窗口期短；GRPO 训练 7B 模型需要几张 A100 级显卡。

**备选：**
- 差分隐私合成临床笔记：方向已挤，Term2Note 等已在做；
- 联合分布对齐：适合作为主方向里的一个模块。

### 2.5　病历为什么需要长程一致性，故事怎么讲

**需求从哪里来：**
- 国内一次住院本身就是十几份文书：入院记录、首次病程、日常病程、查房、手术、出院记录。《病历书写基本规范》要求前后一致，医院有病历质控。
- 国外一个病人是多次就诊连在一起的。

**病人级任务都依赖整个病人自洽：**
- 预后预测；
- 跨文档摘要；
- 临床智能体考场；
- 纵向数据共享。

单篇写得像，只够单篇级任务用。

**故事一句话：** 别人证明"每一页都像病历"，我们证明"整本是同一个病人"，并且用程序证明，不用评委。

**建议口径：** 以"一次住院的多份文书"为最小单位。这样与 LLM-CARe、RareSyn 处于同一任务范畴，多次就诊作为扩展实验。

### 2.6　这个领域的数据与对比惯例（2026-10-01）

- LLM-CARe：医院私有病历做参考集，不发布；下游选择题自建，干扰项规则自定；评委、下游、基线脚本未公开。
- RareSyn：JARVIS-D（腾讯，知识图谱只公开子集）与 JarvisD2（GPT-4 从执业医师考题中抽出的病例描述）；测试集 288 条、80 条；对手只有原始数据与 MedSyn；无代码。
- NHS：不用真实数据，无基线，同一模型当评委。
- ClinGen：18 个公开数据集，同一生成器下比 ZeroGen、DemoGen、ProGen、S3，代码公开。
- 成因：生成任务没有公认考场；真实病历难拿（MIMIC 需协议，且对送入商业 API 有使用限制，细节待核实；国内缺公开电子病历）。
- 对策：各方法换同一生成器底座重跑，不搬表格数字；用公开数据、发布数据与代码、每表放"真实数据训练"与平凡对照两行。

### 2.7　LLM-CARe 为什么跟 Self-Refine 比（2026-10-01）

- 跟母本比本身是必须的；问题在于：把母本改名后包装成对手、比赛条件不对等（独享语料词表、调用预算未对齐）、消融是母本已做过的复刻。
- 正确的表应有五行：Self-Refine（预算对齐）；Self-Refine + 语料词表；Self-Refine + 17 条检查表；LLM-CARe 全套；真实病历。

### 2.8　自我纠错的两维结构（2026-10-01）

| 错误信号从哪来 | 训练时（改参数） | 推理时（不改参数） |
|---|---|---|
| 人 | InstructGPT 的 RLHF（对齐，是前身） | — |
| 大模型自己 | Constitutional AI | Self-Refine（Huang 等 2024：无外部信号常越改越差） |
| 外部工具或真值 | SCoRe、DeepSeek-R1 | CRITIC、Reflexion |

- 纯提示词自我纠错：对"好不好"有些用，对"对不对"基本无用（Self-Refine 数学 +0.2，94% 反馈为"看起来没问题"）。
- 病历的"好"可拆：格式、性别—诊断、侧别、剂量、过敏、与结构化记录一致、文书间一致，这些可程序核验；只有"像不像医生写的""推理是否合理"需要校准过的评委。
- "阶段一"可以自己造：真实病历当正例，程序埋雷当负例（借 Re3 负例构造与 CriticGPT 埋错）。

### 2.9　缝合本质（2026-10-01）

- 四篇都没有训练生成器或批评器；训练过的模型只出现在评测环节（下游考生）。
- 共同模式：从造数据、自我纠错、评委三条国外线上，各取 2023 年那一代只靠提示词的版本，换上病历的皮，再用自己控制的评委和考卷证明自己。三条线后来都走向训练出来的批评器、可验证奖励、校准过的评委，它们一条都没跟。
- 强化学习只能在开源权重模型上做；API 模型无法自行强化学习。这类论文的贡献在训练数据、奖励定义与训练配方，不在网络结构。

### 2.10　两张 RTX 5090 的路线评估（2026-10-01）

| 路线 | 训练时间 | 故事 | 风险 |
|---|---|---|---|
| 1 更高级的免训练（状态注入、规则核验、多采样挑最好、按错修改） | 无 | 中：部件是 2022—2023 年的国外成品 | 低 |
| 2B 训练病历查错器（自动埋雷，0.5—1.5B 全参或 7—8B LoRA） | 几小时到一天 | 中高：对应 CriticGPT 一代，病历上无人做 | 低到中，依赖真实病历来源 |
| 2C 小模型 GRPO（3—4B + LoRA，程序化一致性奖励） | 数天到数周 | 高 | 高 |

- 推荐：先做 2B，并让查错器驱动免训练流程（主论文）；再以查错器加规则为奖励做 2C（扩展）。"医院数据不能出院、需要本地小模型"使有限算力成为卖点。
- 待落实：正例来源（MIMIC-IV 出院小结需协议；PMC-Patients 公开但非真实文书；合作医院中文病历难公开）。5090 的 CUDA、PyTorch、vLLM、TRL 版本兼容需实测。
